1 Conceptual Design

1.1 Functional Modeling

Functional modeling represents the processes, data transformations, inputs, and outputs that define the operational behavior of the Touchless Hospital Management System (Touchless HMS). The system addresses Healthcare-Associated Infections (HAIs) in clinical environments by enabling hands-free access to hospital services through optical air gestures captured by the Leap Motion Controller (LM-010).

1.1.1 Core System Functions & Data Flow

The functional boundaries of Touchless HMS encompass four main process pillars:

  • Contactless Access Control & Biometrics: Captures open-palm gesture hold events (1.5 seconds) or authenticates credentials against SHA-256 hashed passwords in the relational database.
  • Specialist Discovery & Appointment Booking: Dynamically loads departments, filters physician rosters based on clinical criteria, and persists appointment records with foreign key integrity.
  • Physician Clinical Encounter Management: Provides physicians with dynamic schedules, patient medical histories, touchless imaging zoom/pan, and electronic prescription (e-prescription) submission.
  • Nurse Ward Telemetry & Alarm Management: Displays real-time vital telemetry (SpO2, Heart Rate, BP, Temp) with touchless horizontal hand wave dismissal for clinical alarms in sterile zones.

1.2 Structural Modeling

Structural modeling specifies the static composition of Touchless HMS, encompassing the multi-tier architectural layout, UML class hierarchies, component definitions, and physical interfaces.

1.2.1 Multi-Tier System Architecture

Touchless HMS employs an industry-standard 3-Tier Service-Oriented Architecture (SOA):

  1. Presentation Tier (Contactless Kiosk & Web Portals): Built with HTML5, Glassmorphism CSS design tokens, and modular JavaScript (`dashboard-patient.html`, `dashboard-doctor.html`, `dashboard-nurse.html`, `login.html`). Incorporates the `leap-gesture.js` engine that interfaces with the local WebSocket daemon (`ws://127.0.0.1:6437/v6.json`).
  2. Application Tier (RESTful API & Router Engine): Modular PHP 8.2+ stateless REST API controllers (`api/*.php`) backed by Apache `.htaccess` rewrite rules and `js/api.js` universal adaptive client. An alternative Node.js runtime (`server.js`) is also maintained for zero-configuration standalone deployments.
  3. Data Persistence Tier (Dual-Engine Relational Storage): Powered by `api/db.php`, a dual-engine PDO abstraction layer that connects to local MySQL / MariaDB (Port 3306), with automatic failover to embedded SQLite (`database/touchless_hms.db`).

1.5 Detailed Analysis of Project Design Revisions (Rubric 1.b)

In accordance with Evaluation Rubric Component 1.b (20 points), this section documents all architectural, structural, and functional modifications implemented since the initial project submission:

Design DimensionInitial State (Milestone 1)Revised State (Milestone 2)ClassificationAcademic & Technical Rationale
Backend Architecture Pure client-side static JavaScript with hard-coded dummy data. Dual-engine PHP 8.2+ REST API backend with modular endpoints (`api/*.php`). Major Addition Directly addressed faculty feedback: previous prototype lacked application logic and server-side processing.
Relational Database No database; client-side memory only. ANSI SQL database (`touchless_hms`) with strict Foreign Key constraints and triggers. Major Addition Ensures persistent patient records, auditable appointment transactions, and data durability.
Database Engine Resilience None. Dual-Engine PDO (`api/db.php`): auto-connects to MySQL 3306; auto-cascades to embedded SQLite. Architectural Enhancement Guarantees 100% kiosk demonstration availability even if the external MySQL service is disabled.
Server URL Routing Single static server with 404 route failures on Apache. Apache `.htaccess` rewrite rules (mod_rewrite + MultiViews) + PHP `router.php`. Major Addition Eliminated 404 Not Found errors on Apache 2.4.58 (XAMPP Port 80) when calling REST routes.
Client API Abstraction Hardcoded absolute URLs (`fetch('/api/...')`). Universal Adaptive Client (`js/api.js`) computing relative base URLs dynamically. Structural Revision Enables the system to operate seamlessly within Apache subfolders (e.g. `/touchless-hopital/`) or root domains.
Referential Integrity Appointments lacked department foreign keys. Enforced `department_id REFERENCES departments(id)` on `appointments`. Database Enhancement Eliminated scheduling orphan records and ensured strict relational integrity for clinical reporting.
Patient Registration Hardcoded accounts only. Dynamic registration API (`POST api/auth.php?action=register`) with Civil ID and blood type. Feature Addition Enables new outpatient onboarding directly from the contactless kiosk interface.

2.2 Detailed Breakdown of Implemented Features

  • Dual-Engine Database Engine (`api/db.php`): Connects transparently to MySQL/MariaDB or SQLite, executing identical parameterized PDO queries with zero code divergence.
  • Dynamic Outpatient Kiosk (`dashboard-patient.html`): Features real-time department filtering, live physician search with 280ms input debouncing, hands-free appointment creation, and instant patient timeline synchronization.
  • Physician Clinical Portal (`dashboard-doctor.html`): Chronological appointment queue, patient clinical dossier review, and digital e-prescription issuance with transactional database persistence.
  • Contactless Gesture Pipeline (`js/leap-gesture.js`): Real-time WebSocket connection to Leap Motion Orion v4.1 / Gemini daemon (`127.0.0.1:6437`), rendering a smooth 60fps virtual hand cursor with SVG radial dwell animation and Web Audio auditory feedback.
  • Universal Routing Engine (`.htaccess` / `js/api.js`): Resolves API endpoints dynamically regardless of server environment (Apache, Node.js, or PHP CLI server).

2.3 Software Demonstrations & System Interface Walkthroughs

The system demonstration presents the following three operational workstations:

Workstation 1: Contactless Patient Appointment Kiosk (`dashboard-patient.html`)

Outpatients interact with the kiosk hands-free. The system displays their profile header (Civil ID, Blood Type, Active Status) followed by quick-health cards. Hovering an open hand over a department pill (e.g. Cardiology) triggers the dwell timer and dynamically retrieves specialist doctors from the database. Patients then air-tap Select & Book to confirm their appointment, which instantly updates their personal visit schedule.

Workstation 2: Physician Clinical Workstation (`dashboard-doctor.html`)

Physicians view their live daily schedule populated directly from the `appointments` table. Selecting an appointment loads the patient's medical history, vital signs, and consultation records. In the e-prescription tab, doctors issue medications (e.g. Amlodipine Besylate 5mg), which are committed to the database and reflected in the patient's portal.

Workstation 3: Role-Based Authentication & Registration Portal (`login.html`)

Features clean glassmorphism styling with role switcher tabs (Patient / Doctor / Nurse), self-registration form for new outpatients, and one-click database demo buttons to facilitate academic grading.

2.5 Major Technical Issues & Challenges Encountered

1. Apache 404 URL Rewrite Conflicts on Port 80

Problem: When running under standard Apache 2.4.58 (XAMPP Port 80), REST calls to `/api/auth/login` and `/api/doctors` returned `404 Not Found`. Apache searched for physical folders rather than executing `api/auth.php`. Furthermore, when hosted in subdirectories, absolute URLs routed outside the project.

Solution: Created root and directory `.htaccess` files enabling `RewriteEngine On` and `Options +MultiViews`. Developed `js/api.js` to dynamically compute relative base paths, ensuring seamless compatibility across all hosting environments.

2. Absence of Tactile Feedback in Air Gestures

Problem: Without physical surface contact, users experience uncertainty during selection, leading to accidental double-clicks.

Solution: Developed a multi-modal feedback system combining a visual SVG radial progress ring, dual-frequency Web Audio chimes (880 Hz confirmation tone), and instantaneous CSS scaling on active target elements.

3. Database Driver Interoperability

Problem: Evaluators' machines may not have an active MySQL service running, which would cause database connection failures.

Solution: Engineered an automatic cascade in `api/db.php`. If MySQL is unreachable, it immediately falls back to the embedded SQLite database (`touchless_hms.db`), ensuring reliable academic demonstrations in any setting.
